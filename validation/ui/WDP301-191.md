# WDP301-191 - Maintenance history UI

## Approved scope

The user approved retaining the existing filters, columns, data, and behavior,
using the prototype table and shared Panel presentation for the detail page, and
omitting prototype statistics without corresponding data. The prototype does not
provide a detail screen and its cost and technician columns do not match the API.
The existing server-side search, date validation, status and sorting filters,
pagination, scoped access, detail links, read-only information, and return URL
remain in place. No backend, API, route, permission, or dependency was changed.

The list uses PageContainer, PageHeader, Panel, FormField, shared atomic controls,
DataTable, and EmptyState. The detail uses PageHeader and Panel. The retained image
component displays equipment images and the shared Badge preserves status labels.
No new shared component was introduced.

## Regression evidence

The original 18 history tests passed before implementation. A new regression
checks facility-only history without a linked task in both list and detail; all
19 tests passed on the original and migrated pages. Existing assertions remain
unchanged. The initial test query for the new case was corrected to target the
status text rather than the option with the same label.

## Prototype checklist and browser evidence

- [x] Page header, table, tokens, type, spacing, radius, shadow, and pagination
  compared with the live prototype and source, with the approved differences above.
- [x] List and detail checked at 1440, 768, and 375 pixels; document width equals
  viewport width. Long equipment names, room numbers, descriptions, names, and
  work results fit within 375 pixels after grid and column constraints.
- [x] Empty, loading, and error states checked in the browser; status text, date
  validation, errors and retry, scoped 404, and access checks covered by tests.
- [x] The table scroll region accepts keyboard focus. Opening a detail preserves
  status and page parameters on its return link; browser requests remained GET-only.
- [x] Queries, API calls, validation, routing, permissions, and existing behavior
  assertions remain unchanged. No test assertion was altered for the migration.

An initial browser pass exposed overflow in the detail grid for unbroken strings;
the final build uses constrained grid tracks and a bounded target column. Browser
automation ran outside the sandbox to access Edge's debugging port.
