# WDP301-190 - Maintenance fault reporting UI

## Scope and approved differences

The user approved preserving the existing room, equipment, and facility reporting
modes, target search, equipment image, maintenance action and safe-use flags, and
truthful confirmation details within the prototype presentation. Prototype-only
title and severity fields are excluded. Existing accessible labels remain.

The page reuses PageContainer, PageHeader, Panel, FormField, atomic controls,
Alert, and EmptyState. The form follows the prototype grid, spacing, and rounded
submit action. Native checkbox inputs preserve the existing validation focus
target. No component, dependency, API, hook, validation, route, or permission was
added or changed.

## Regression evidence

The original 15 tests passed before presentation changes. Two additional tests
cover facility-only payloads and truthful confirmation, and equipment selection
and image retention after an empty search. All 17 tests passed both before and
after the presentation change. Existing assertions were not changed.

## Limitations

Browser checks use local QA responses through the normal API client and auth
provider. They do not verify database writes or production authentication. No
backend code was changed; backend checks and a manual screen-reader session are
outside this verification. Screenshots remain local. Unrelated user edits remain
outside this isolated worktree. The approved prototype differences above are the
only design exceptions.
