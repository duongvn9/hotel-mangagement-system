# WDP301-187 — Room management UI

## Scope and approved differences

The room catalog and create/edit dialog at `/manager/rooms` reuse the prototype's page header, table, search/filter toolbar, typography, semantic tokens, icons, loading skeletons, empty state, and dialog structure.

The user explicitly approved retaining notes, the activity filter, deactivation/reactivation, inactive or missing room-type warnings, safe-integer floor validation (including zero and negative floors), and all four existing operational statuses. The prototype's price column and delete action were intentionally excluded. Existing accessible headings, field labels, room actions, API calls, guards, permissions, search debounce, and server pagination remain.

Native confirmations now use the existing `AlertDialog` organism. The reservation warning and PATCH payloads remain unchanged: direct deactivation sends only `isActive: false`, while a regular save or reactivation retains its existing validation and changed-field payload. The editor prevents dismissal during a pending save and restores focus on close.

`DataTable.paginationLabel` is an optional presentation prop that preserves the existing named pagination landmark. The default footer is unchanged when the prop is absent; the component catalog and regression test document this option.

## Test changes

- Baseline: all 31 existing room tests passed before production edits.
- Confirmation tests were changed first and failed against native `window.confirm`; the shared table landmark assertion also failed before its prop was implemented.
- Assertions now wait for loaded rows instead of the skeleton table, and for active-type options before reactivation. The editor test uses Escape and waits for focus restoration after the Radix dialog closes. Pagination text follows the shared `Trang 2 / 3` format.
- Additional regressions cover an unchanged edit without a request, checkbox deactivation retaining other edits, and blocked Escape/close actions during a pending save.
- Native-dialog mocks were removed because the editor now uses the shared Radix dialog.

## Limitations and exceptions

- No backend code, routes, hooks, API contracts, or dependencies changed. Backend checks and database end-to-end writes were not run for this presentation-only ticket.
- Browser data is controlled QA data, not a live MongoDB write/read round trip. Unit/integration tests verify request payloads and validation. No manual screen-reader session was performed.
- The build runs with `npm run build` in a clean source copy using the existing dependency directory. The task's production files must match that copy byte for byte. This avoids the previously locked `frontend/dist` and excludes unrelated user Vite configuration changes; no existing files are deleted.
- The user-approved prototype gaps and screenshot-upload waiver are the only intentional scope differences. The prototype-only save notice, mock store, role switcher, and deletion are not shipped.
- Unrelated user work remains outside this ticket's commit.
