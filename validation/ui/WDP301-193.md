# WDP301-193 - Revenue report UI

## Approved scope

The user approved keeping the existing real transaction data, filters, warnings,
bar chart, and detailed tables, while applying prototype cards and Panels. The
prototype's room-type revenue, online ratio, and simulated file export are not
provided by the current API and are excluded. Existing query, validation, date
semantics, labels, empty states, and access remain.

The page uses PageContainer, PageHeader, Panel, StatCard, FormField, atomic
controls, Alert, Badge, and DataTable. The existing accessible chart and data
tables retain the complete series, including zero buckets. No dependency,
backend, API, route, or permission was changed.

The shared ReportPeriodFields had to be migrated to atomic controls to remove
deprecated imports without duplicating its logic. This also changes the visual
styling of the three period controls on the operational report. Both pages keep
the same labels, values, error associations, and behavior; the operational tests
were run as well. The user was informed of this shared-component effect.

## Regression evidence

The original suite passed 24 tests. An additional test checks that a period with
only failed transactions is not reported as empty; the 25 tests passed before the
UI change. The final focused revenue and operational suites passed 40 tests.
Existing assertions remain unchanged.
