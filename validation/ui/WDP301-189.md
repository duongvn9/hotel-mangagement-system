# WDP301-189 — Service management UI

## Scope and approved prototype gaps

The user approved retaining service images, descriptions, units, billable/free settings,
activity filtering, and deactivate/reactivate actions in the prototype table and dialog
presentation. Categories and deletion are excluded because the existing API does not
support them. The existing heading, labels, route guards, API contracts, validation,
300 ms search debounce, and server pagination remain.

The page reuses `PageContainer`, `PageHeader`, `DataTable`, atomic controls and badges,
and the existing image viewer. The editor reuses `Dialog`, `FormField`, and `AlertDialog`.
The image picker uses its existing prototype appearance. No dependency or shared
component was added. Confirmation messages remain unchanged; confirmations now use
the shared accessible dialog instead of `window.confirm`.

## Test evidence and assertion changes

- The original implementation passed all 39 service tests in the clean baseline copy.
- Before confirmation implementation, four tests failed because the shared confirmation
  dialog was absent. The editor focus assertion also needed to wait for Radix cleanup.
- After implementation, all 39 service tests passed.
- The table test waits for a loaded row because the shared table renders during loading.
  Presentation assertions now follow the prototype table and rounded controls.
- Pagination assertions accept the shared `Trang 2 / 3` spacing. Editor tests send
  Escape instead of the native dialog cancel event and await focus restoration.
- Confirmation tests interact with the alert dialog and retain their draft, cancellation,
  reload, validation, and request payload assertions. Direct toggles still send only
  `isActive`; regular saves still send only changed fields. Image upload sequencing and
  retry behavior remain covered by the existing tests.

## Limitations

No backend code, API, route, permission, or dependency was changed. Browser checks use
read-only QA fixtures through the normal API client and auth provider; they do not prove
database writes or production authentication. No manual screen-reader session is claimed.
Unrelated user edits are outside this task. Build copies use the existing dependencies
and exclude unrelated configuration changes. Browser automation required execution
outside the sandbox because the sandboxed Edge process did not expose its debugging port.
The approved prototype gaps are the only design exceptions; no other project rule was waived.
Push, merge, screenshot upload, and Jira completion have not been performed.
