# WDP301-194 - Operational report UI

## Approved scope

The user approved preserving the real report data, period filters, warnings,
chart, detailed tables, and separate period and snapshot sections while applying
the prototype's visual components. The prototype's metrics and charts that the
current API does not supply are excluded. Query, validation, routes, and access
remain unchanged.

The page uses PageContainer, PageHeader, Panel, atomic controls, Alert, FormField,
and DataTable. The chart and table retain every series bucket and metric. Long
category labels wrap within their cards. A regression test covers unknown
occupancy and maintenance status values.

## Checks

- `npm run typecheck`, `npm run lint`, `npm run format:check`, and `npm run build`
  passed on the updated main. Lint reported three existing Fast Refresh warnings
  in vendored primitives; build reported the existing large-chunk warning.
- The operational report suite passed 16 tests before the UI migration. The
  service-order assignment suite passed 38 tests when run separately after two
  interrupted full-suite runs reported one failure in that suite.
- `npm test -- --pool=vmThreads --maxWorkers=1 --vmMemoryLimit=256MB --testTimeout=20000`
  passed: 73 files and 1,095 tests.
- Legacy-class, forbidden-import, and hard-coded-color scans on the changed
  feature files found no matches. `git diff --check` passed.

## Browser verification

The live prototype and application were compared at widths of 1440, 768, and
375 pixels. The document did not overflow at these widths or with a long
category label. Loading, empty, missing-source, and error states were exercised;
the table scroll region accepted keyboard focus. Captured API requests were GET
requests. The app used local QA responses rather than production data.

Screenshots remain local under `.task-WDP301-194/`. Production login, a live
database, and a manual screen-reader session were not verified. Prototype
differences described above were approved by the user.
